- `classes.dex` (DEX 038, 1,065,032 bytes)
- binary `AndroidManifest.xml`
- `resources.arsc`
- AndroidX/Kotlin runtime classes and resources

The application package in the binary manifest is `com.antutu.ABenchMark`.
The manifest reports min SDK 26, target SDK 35, compile SDK 37, versionCode 1,
versionName 1.0, and Android Gradle Plugin metadata 9.4.1.

## MainActivity behavior recovered

- Extends `androidx.activity.ComponentActivity`.
- Registers an Activity Result launcher for overlay settings.
- On creation, removes transition animation, sets a transparent background,
  clears `FLAG_DIM_BEHIND`, adds window flags `0x01000218`, sets window alpha
  to zero, enables immersive sticky mode, installs a transparent full-screen
  View, then checks permissions and starts the service.
- Overlay permission is the only permission gate for activation.
- Battery optimization and notification permission are optional and are not requested during activation.
- The service is started with `ACTION_START_SERVICE`.
- The Activity shows the original activation toast.
- In multi-window mode it finishes. Otherwise it moves the task to the back
  after 500 ms.
- On resume, it rechecks overlay/service state and backgrounds the task after
  200 ms when the service is already running.
- On Android 11+, it hides status/navigation bars and sets transient-by-swipe
  behavior. Older versions use systemUiVisibility value 5382.

## PerformanceService behavior recovered

- Service class name: `com.antutu.ABenchMark.PerformanceService`.
- `ACTION_START_SERVICE` value: `com.antutu.ABenchMark.ACTION_START`.
- `ACTION_STOP_SERVICE` value: `com.antutu.ABenchMark.ACTION_STOP`.
- Notification channel: `iqoo_performance_service_channel`.
- Notification ID: 1001.
- Channel importance: `IMPORTANCE_LOW`.
- Channel description: `Notification channel for Performance Service`.
- `onCreate()` stores a WeakReference and initializes service state.
- `onStartCommand()` stops on ACTION_STOP; otherwise it creates the notification
  channel and enters foreground before attaching the overlay. On API 34+, the service type is
  `FOREGROUND_SERVICE_TYPE_SPECIAL_USE` (`0x40000000`).
- `onBind()` returns null.
- `onDestroy()` detaches the overlay and clears static state.
- Heartbeat interval: 3000 ms. The runnable invalidates the overlay View and
  schedules itself again only while the static running flag is true.
- Overlay width/height: 2 x 2 pixels.
- Overlay type: 2038 (`TYPE_APPLICATION_OVERLAY`).
- Overlay flags: 16777496 (`0x01000118`).
- Pixel format: -3 (`PixelFormat.TRANSLUCENT`).
- Gravity: 8388659 (`TOP | START`).
- Position: x=0, y=0.
- Alpha: 0.02.
- View layer type: 2 (`LAYER_TYPE_HARDWARE`).
- Overlay failures are recorded in local diagnostics with exception type and message.
- ROM guidance uses public Android `Build` fields and does not claim a specific
  vendor OS when its build identifiers do not expose one.

## Fidelity boundary

This is a source-level reconstruction of the app-owned classes and resources,
not a recovered copy of the original Kotlin source. DEX does not retain original
comments, formatting, source file structure, or exact Kotlin syntax. Some
Kotlin-generated callback bridge names are compiler artifacts and are replaced
by equivalent Java callbacks.

The original package and component names, Activity
transparency/background behavior, 500 ms and 200 ms delays, service lifecycle,
notification action, overlay geometry, and heartbeat timing are represented.

No CPU-frequency sysfs writes, vendor performance service calls, benchmark
protocol calls, or OEM boost commands were present in the recovered app-owned
DEX methods. This reconstruction therefore does not add any such behavior.
Package identity or a foreground service alone cannot guarantee that OriginOS
will activate a benchmark performance profile. The output is signed with a
new key and cannot reproduce the original signing certificate.
